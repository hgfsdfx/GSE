# Blender 에셋 로더와 애니메이션

`assets/nox_lowpoly/README.md`의 슬롯, 좌표, 팔레트 규격을 구현한다. 정적 팩과 함께
`assets/nox_animated/rig_catalog.json`의 공용 NPC 골격, 리깅 파트, 로봇을 사용한다.
Blender 편집 원본인 `.blend`를 직접 읽지 않고, 함께 내보낸 glTF 2.0 GLB를 읽는다.

## 현재 게임에 연결한 범위

- 플레이어: `ghost` 프리셋.
- 패치: `patch`. 일반 NPC: 직업에 맞는 `hunter_01`, `raider_01`, `hacker_01`,
  `merchant_01`, `seeker_01`, `guard_01` 프리셋.
- 정찰 몬스터: `01_Sentinel`. 장갑형: `03_Juggernaut`. 현재 프로토타입 보스는
  Sentinel을 크게 표시한다. 다른 로봇도 카탈로그를 통해 로드할 수 있다.
- 도시 건물 및 주택: Building 슬롯의 모델을 기존 폭·깊이·높이에 맞춰 표시한다.
  이동 판정, 주택 소유권, 길 찾기는 기존 Actor 데이터를 사용한다.
- 건물의 소등 상태는 인스턴스 발광 배율에 전달한다. 소등된 발광 재질은 바탕색도
  어두워지고, 건물 자체는 유지된다. 발광은 기존 HDR/Bloom 경로로 들어간다.
- 나무, 바위, 풀, 관목, 화단, 도시 소품은 `ModelActor`로 추가 배치할 수 있다.
  이번 변경에서 자연물을 월드 전체에 무작위로 추가하지는 않는다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `SimpleGame/ModelAsset.*` | glTF/GLB, 노드 계층, 재질, 스킨, 클립 디코딩 및 검증 |
| `SimpleGame/ModelMath.*` | 열 우선 행렬, TRS, 쿼터니언 보간 |
| `SimpleGame/AssetLibrary.*` | 카탈로그, 고정 인덱스, 프리셋 조립, CPU 모델 공유 |
| `SimpleGame/ModelBatch.*` | 별도 3D 정점 아틀라스, 디스크 캐시, 본 행렬 스트리밍 |
| `SimpleGame/RendererModels.cpp` | 기존 삼각형 인스턴스 스트림에 모델 등록 |
| `SimpleGame/PrototypeModels.cpp` | Actor 이동 상태와 외형·애니메이션 연결 |
| `SimpleGame/ModelActor.*` | SceneGraph에서 관리하는 재사용 가능한 모델 Actor |
| `SimpleGame/Shaders/SolidRect.vs/fs` | GPU 스키닝, 2.5D 투영, 팔레트·발광·조명 |

`ModelAsset`은 노드 번호가 부모 순서라고 가정하지 않는다. 부모부터 계산한 월드 행렬과
inverse bind 행렬을 사용한다. 서로 다른 NPC 파트의 본 번호도 같다고 가정하지 않는다.
공용 애니메이션 파일의 본 이름으로 연결하고, 부모 이름과 기본 월드 자세가 호환되는지 검사한다.

모듈형 NPC의 완성형 메시를 인물마다 만들지 않는다. 프리셋들은 같은 파트를 참조하며,
`NPC_Common_Animated.glb`는 애니메이션 소스로만 사용하고 그 안의 예제 몸체는 중복 표시하지 않는다.

## 좌표와 재질

- GLB의 Y-up 좌표를 사용한다. 게임 월드 `(x,y)`에는 GLB `(x,-z)`를 대응시키고
  GLB y를 높이로 사용한다. 2.5D 투영 계수는 기존 `.82`, `.43`이다.
- NPC 표준 배율은 미터당 24 월드 단위이며 카메라 확대율을 곱한다.
- 런타임 경계 상자는 GLB의 정점과 기본 골격 자세에서 계산한다.
  카탈로그의 Blender Z-up 경계를 GLB 경계로 오인하지 않는다.
- 팔레트는 README의 재질 이름 치환 규칙을 따른다. 색상은 이미 선형 RGB이므로
  기존 2D UI 색상과 구분해 감마 변환을 적용한다.
- 지금은 바탕색·발광·노멀을 사용하는 간단한 야간 조명이다. metallic/roughness를
  이용한 PBR 반사나 그림자 맵은 구현하지 않는다.

## 애니메이션

노드 translation/rotation/scale 채널의 LINEAR, STEP, CUBICSPLINE을 읽는다.
회전의 선형 보간은 최단 경로 쿼터니언 보간, cubic 결과는 쿼터니언 정규화를 사용한다.
정규화된 웨이트와 최대 4개의 본 영향을 GPU에서 처리한다.

현재 NPC·플레이어·몬스터는 실제 이동량에 따라 Idle/Walk/Run을 선택하고 이동 방향으로 회전한다.
이동 속도에 맞춰 재생 속도를 대략 조절한다. 정지·달리기 전환은 즉시 이루어지며
클립 간 블렌딩은 후속 범위다. 기본 애니메이션 샘플링은 30Hz이며 Actor 이동은 기존 실시간 갱신을 유지한다.

GLB에 포함된 Turn, Jump 등 다른 클립도 이름으로 지정할 수 있다.
`ModelActor.clip`, `animationTime`, `loop`로 반복/일회 재생을 제어한다.
루트 이동·회전은 모델의 시각적 포즈에 반영되지만, Actor 이동·점프 충돌이나 AI 목표에
자동 적용되지는 않는다. 현재 이동은 게임 코드가 결정하는 in-place 방식이다.
스마트폰의 기존 2D 표시는 유지되며 손 본 소켓에 부착하는 기능은 별도 확장 대상이다.

## 캐싱과 배칭

1. 시작할 때 카탈로그와 사용 가능한 프리셋·환경·로봇 모델을 한 번 디코딩한다.
2. CPU 모델은 경로별로 공유하고, 읽기 실패도 기억해 매 프레임 재시도하지 않는다.
3. 처음 표시할 때 공유 정점을 3D 아틀라스에 올린다. 이후 NPC 수가 증가해도
   위치·회전·팔레트·본 행렬만 추가한다. 애니메이션마다 정점을 다시 만들지 않는다.
4. 확장한 삼각형은 `실행파일 폴더/MeshCache/models-v1/*.gmodel`에도 저장한다.
   키에는 원본 GLB와 외부 버퍼 내용의 해시가 포함된다. 수정된 에셋은 새 키를 사용한다.
   캐시 버전·길이·키 해시·정점 체크섬·유한값을 검사하며 손상 시 원본으로 복구한다.
   이 캐시는 원본 파싱을 대체하는 전체 씬 캐시가 아니라 GPU용 정점 캐시다.
5. 기존 2D `MeshCache/v3`와 3D 아틀라스는 분리한다. 2D 정점 크기와 기존 캐시 형식은 유지한다.
6. 2D/3D 삼각형은 동일한 인스턴스 스트림에서 `glDrawArraysInstanced`로 제출한다.
   메시나 재질이 다르다는 이유로 별도 draw를 만들지 않는다. 인스턴스·삼각형·본 버퍼
   한도를 넘으면 배치를 나누므로 모든 상황에서 월드 draw가 1회라는 보장은 없다.
7. 조립된 NPC 전체를 한 배치에 예약하고 같은 깊이 그룹에 둔다. 모델 내부 표면은
   깊이 검사로 가리고, Actor 간에는 기존 SceneGraph 정렬 순서를 유지한다.
   HDR 씬에 24비트 깊이 버퍼를 추가했다. UI·후처리 draw는 기존 경로를 유지한다.

CPU 디코딩 정점 예산은 라이브러리 전체 64MiB, GPU 3D 정점 예산은 최대 32MiB와
장치의 texture buffer 한도 중 작은 값이다. 파일 캐시는 64MiB 한도다.
포즈 캐시는 모델당 최대 256개와 약 8MiB 한도 중 작은 개수를 사용한다.
GPU 아틀라스가 가득 차면 해당 모델을 기존 표현으로 대체한다. 자동 LRU 교체나
무한 월드의 모델 스트리밍은 후속 확장 대상으로 남겨 둔다.

로그는 다음처럼 구분한다.

```text
[Asset] Loaded ... nodes=... surfaces=... vertices=... skins=... clips=...
[Asset] Root=... models=... appearances=... vertexBytes=...
[AssetGPU] Upload ... / DiskLoad ... / Atlas full ...
```

기존 `[Profile]`의 실제 DrawCalls와 배치 업로드 바이트에는 모델 제출과 본 행렬도 포함된다.
기존 MeshNew/MeshLoad는 2D 캐시 지표이며, 모델 최초 로딩·업로드는 위 Asset 로그에서 확인한다.

## 새 에셋 추가

1. Blender에서 미터 단위·발밑 피벗을 유지하고 glTF 2.0 GLB로 내보낸다.
2. 정적 파트·환경은 `nox_lowpoly/mesh_catalog.json`에 슬롯과 새 인덱스를 추가한다.
   리깅 파트·로봇은 `nox_animated/rig_catalog.json`에 경로와 골격 ID를 추가한다.
   기존 인덱스를 재번호하지 않는다. 파일 정렬 순서는 사용하지 않는다.
3. NPC의 외형은 `npc_presets.json`에 슬롯 조합과 팔레트 인덱스로 등록한다.
   Hair/Accessory만 0으로 생략할 수 있다. 새 리깅 파트만 추가한 프리셋도 사용할 수 있지만,
   그 프리셋에 정적 파트가 없으면 정적 모델로의 대체는 불가능하다.
4. 공용 골격을 사용하는 파트는 본 이름·부모 관계·기본 자세를 동일하게 유지한다.
   다른 골격은 별도 로봇 모델처럼 자기 GLB의 클립을 사용한다. 자동 리타기팅은 하지 않는다.
5. 게임을 다시 시작해 변경을 읽는다. 파일 감시·실시간 재로딩은 현재 제공하지 않는다.

SceneGraph에 환경물을 배치하는 예:

```cpp
auto& tree = level_.Scene().Spawn<ModelActor>(0, ModelActor::Kind::Environment, "Tree", 1);
tree.SetWorldPosition({300, 400});
tree.scale = {24, 24, 24};

auto& robot = level_.Scene().Spawn<ModelActor>(0, ModelActor::Kind::Robot, "04_Hound");
robot.SetWorldPosition({400, 450});
robot.clip = "Walk";
robot.loop = true;
```

이 예는 `Prototype` 내부 기준이다. 일반 `ModelActor`는 표시용이며 충돌·상호작용·저장 규칙은
배치하는 게임 시스템에서 추가해야 한다. 기존 NPC·EnemyActor는 기존 동작을 계속 사용한다.

## 파일 위치와 빌드 연결

Visual Studio 프로젝트에 새 소스 파일을 등록했다. Build 후에는 GLB/glTF/bin/json만
실행파일 옆 `assets/`로 복사한다. `.blend`와 프리뷰 이미지는 런타임에 복사하지 않는다.
정상 배포 시 실행파일 옆 `Shaders/`와 `assets/`를 함께 배포한다.

검색 순서는 절대 경로 환경 변수 `GSE_ASSET_ROOT`, 실행파일 폴더의 `assets`,
실행파일 상위 폴더의 `assets`다. `GSE_ASSET_ROOT`는 `nox_lowpoly`와 `nox_animated`를 포함한
assets 폴더 자체를 가리킨다. 카탈로그 상대 경로와 외부 glTF 버퍼는 이 폴더 밖으로 나갈 수 없다.

## 현재 지원 경계와 확인 상태

현재 제공된 75개 GLB는 텍스처가 없고 불투명 재질을 사용한다. 이 규격을 우선 지원한다.
외부 텍스처, 투명 BLEND 재질, 모프 타깃, Draco/meshopt 압축, 4개를 넘는 본 영향,
필수 미지원 확장은 오류 로그와 함께 거부한다. 다른 선택적 PBR 확장은 표현을 보장하지 않는다.
GLB 및 `.gltf`의 외부 `.bin`·data URI 버퍼, 인덱스·인터리브·정규화·sparse 접근자를 읽는다.

소스·프로젝트 XML·카탈로그와 실제 GLB 구조를 대조했다. 공용 NPC 파트의 본 기본 TRS가
애니메이션 소스와 일치함도 데이터에서 확인했다. 요청에 따라 게임 빌드·실행·화면 확인 및
성능 측정은 수행하지 않았다. 첫 사용자 확인에서는 모델 표시, 걷기/달리기, 건물 소등,
에셋 폴더를 찾지 못할 때의 기존 표현, DrawCalls와 프레임 시간을 확인하면 된다.

파서와 JSON 라이브러리의 버전·출처·라이선스는
`SimpleGame/Dependencies/ASSET_LOADER_NOTICES.md`에 기록했다.
