# 녹스 로컬 월드 모니터

## 실행

Python 3.9 이상이 필요하다. 추가 패키지는 사용하지 않는다. `http://127.0.0.1:8765`는 서버를 실행한 동안에만 연결할 수 있다.

프로젝트 루트의 PowerShell에서 아래 실행기를 사용하면 사용 가능한 Python을 찾아 서버를 숨김 창으로 실행하고 브라우저를 연다. Codex에 포함된 Python, 일반 `python`, `py` 런처 순서로 확인하며 Windows Store 실행 별칭은 제외한다. 이미 같은 포트에서 모니터가 실행 중이면 기존 서버를 사용한다.

```powershell
powershell -File .\tools\start_monitor.ps1
```

서버 로그는 `monitoring/server-8765.log`와 `monitoring/server-8765.error.log`에 기록한다. 실행기는 서버 PID를 출력하며 종료할 때 `Stop-Process -Id 출력된PID`를 사용할 수 있다. 사용자 지정 상태 파일은 `-State "C:\게임 실행 경로\monitoring\state.json"`, 포트 변경은 `-Port 8766`, 브라우저 자동 열기 해제는 `-NoBrowser`다. 기존 서버가 있으면 현재 데이터 소스를 재사용하므로 다른 상태 파일을 지정하려면 먼저 기존 서버를 종료하거나 다른 포트를 사용한다.

아래는 직접 Python으로 서버를 실행하는 방법이다.

1. 변경된 게임을 빌드하고 실행한다.
2. 저장 파일과 같은 실행 파일 디렉터리 아래 `monitoring/state.json`이 자동 생성된다. 게임 콘솔의 `[Monitor] JSON 상태:`에서 절대 경로를 확인할 수 있다.
3. 프로젝트 루트의 PowerShell에서 실행한다.

```powershell
python tools/monitor_server.py
```

4. 브라우저에서 [로컬 모니터](http://127.0.0.1:8765)를 연다. 종료는 서버 콘솔에서 Ctrl+C다.

서버는 표준 Visual Studio 출력 경로(`x64/Debug`, `x64/Release`, `Debug`, `Release` 및 `SimpleGame` 아래의 같은 경로)를 자동 탐색한다. 여러 상태 파일이 있으면 가장 최근에 갱신된 파일을 사용한다. 사용자 지정 출력 경로 또는 특정 실행을 고정하려면 콘솔에 출력된 경로를 지정한다.

```powershell
python tools/monitor_server.py --state "C:\게임 실행 경로\monitoring\state.json"
```

포트 변경은 `--port 8766`이다. 서버는 `127.0.0.1`에만 바인딩한다. HTML을 더블클릭하는 대신 서버 주소로 접속해야 JSON을 수신할 수 있다.

## 표시 내용

- 전체 NPC 수 / 기준 인원, 생존 인원, 일반 몬스터 / 보스 / 전체 상한, 리젠 간격.
- 마을별 소속 주민 수, 생존 주민 수, 현장 NPC 수, 시장 자금·재고, 주민 자산·부품·깨달음·체력 합계와 직업·행동 분포.
- NPC별 이름·신원·직업·행동·체력·자산·깨달음·현재 위치. 선택하면 목표 위치·마을, 공격 대상, 악명, 작업 시간, 쿨타임과 생존/재산/탐구/약탈 성향을 표시한다.
- 이름/번호 검색, 마을·직업·상태 필터, 체력·자산·깨달음 정렬.
- 마을·NPC·몬스터·플레이어 위치 지도, 최근 120회 수신한 개체 수 추이, 거래·약탈·사냥 수와 최근 이벤트.
- 현재 수신 메시지를 `JSON 저장`으로 다운로드.

소속 주민 집계는 NPC의 `home` 기준이다. 현장 인원은 마을 중심 반경 600 안의 모든 NPC를 세므로 타 마을 방문자가 포함될 수 있다. 체력 비율은 개별 체력 비율의 평균이 아니라 `총 현재 체력 / 총 최대 체력`이다. 개체 수 기준을 벗어나면 상단 카드 테두리가 경고 색으로 표시된다.

게임 실행 중 NPC/몹 개체 수를 모니터링하며, 개체 수를 변경하는 명령은 포함하지 않는다. NPC는 현재 140명, 몹 상한은 일반 상황 18마리 / 보스 포함 9마리다. 보충은 1초마다 최대 2마리다. 기준은 JSON으로 전달되므로 이후 게임 설정 변경도 화면에 반영된다.

## JSON 전달과 갱신

`WorldMonitor`가 게임 스레드에서 **벽시계 기준 0.5초마다** 현재 상태를 문자열로 캡처한다. 게임 일시정지·플레이어 사망 상태도 계속 전달한다. 별도 작업 스레드가 임시 파일을 쓴 후 `state.json`을 원자적으로 교체한다. 대기열에는 최신 메시지 1개만 유지해 저장 장치가 느려도 대기 데이터가 누적되지 않는다. 작업 스레드는 Actor나 SceneGraph를 읽지 않는다.

브라우저는 약 0.5초마다 `GET /api/state`로 `application/json` 메시지를 수신한다. 마지막 생성 시각이 3초 이상 경과하면 ‘데이터 갱신 중단’으로 표시한다. 서버 연결 실패 시에도 마지막 상태는 유지하지만 수신 중단을 명시한다. 게임을 다시 시작하면 `session`이 바뀌고 브라우저의 개체 수 추이가 초기화된다. 개체 수 추이는 게임의 전체 과거 로그가 아닌 해당 브라우저 페이지가 수신한 기록이다. 즉시 부활하는 NPC의 사망 순간은 0.5초 간격 스냅샷에서 생략될 수 있으며 최근 이벤트로 확인한다.

파일 저장 실패는 게임 콘솔에 `[Monitor]`로 표시한다. 파일 생성 성공 여부는 게임 실행 후 확인해야 한다. 구현 시 빌드·실행·브라우저 확인은 수행하지 않았다.

## 별도 JSON 메시지 수신 모드

파일 전달 대신 다른 프로그램에서 HTTP JSON 메시지를 보내려면 아래 모드를 사용한다. 파일 모드와 수신 모드는 별개다. 현재 게임은 파일 모드를 사용한다.

```powershell
python tools/monitor_server.py --receive
```

`POST http://127.0.0.1:8765/api/state`, `Content-Type: application/json`으로 게임의 전체 스냅샷 형식과 같은 JSON을 전송한다. 성공 응답은 `{"accepted":true}`다. 최대 크기는 2MB이며 부분 NPC 업데이트 대신 전체 상태 메시지를 보낸다. 브라우저는 동일한 `GET /api/state`로 최신 수신 메시지를 읽는다. 게임이 만든 메시지를 보내는 예:

```powershell
$worldJsonPath = "C:\게임 실행 경로\monitoring\state.json"
Invoke-RestMethod -Uri http://127.0.0.1:8765/api/state -Method Post -ContentType 'application/json; charset=utf-8' -InFile $worldJsonPath
```

## 스키마 1

| 필드 | 내용 |
| --- | --- |
| `schemaVersion` | `1` |
| `session`, `sequence`, `timestampMs` | 실행 식별 문자열, 스냅샷 증가 번호, UTC Unix 밀리초 생성 시각 |
| `paused` | 게임 일시정지 여부 |
| `counts` | `npcs`, `aliveNpcs`, `expectedNpcs`, `monsters`, `regularMonsters`, `bosses`, `monsterLimit`, `respawnIntervalSeconds`, `loot`, `loadedChunks` |
| `player` | 체력·최대 체력·사망 여부·레벨·자금·부품·깨달음·수배·위치 |
| `society` | 거래·약탈·NPC 사냥 누적 수와 현재 의뢰 목표 |
| `towns[]` | 마을 식별자·이름·위치·방어 반경·자금·재고·소속/현장 인원·주민 합계·분포 |
| `npcs[]` | NPC 신원과 상태, 목표·공격 대상·위치·성향 |
| `monsters[]` | 고유 ID 문자열, 종류, 체력·최대 체력·위치 |
| `news[]` | 최근 사회 이벤트 문자열 |

`npcs[].id`는 저장 파일과 같은 주민 신원 번호이고, `targetNpc`도 이 번호다(없으면 0). `againstPlayer`가 참이면 공격 대상은 플레이어다. `home`, `destinationTown`, `towns[].id`는 0부터 시작한다. 마을의 `jobs`는 사냥꾼/약탈자/해커/상인/탐구자/경비 순서이고, `actions`는 휴식/사냥/추격/거래/해킹/탐구/회복 순서다. 몬스터 `kind`는 0=정찰, 1=장갑, 2=보스다. 좌표는 `{ "x": 숫자, "y": 숫자 }`다. 큰 정수의 브라우저 정밀도 문제를 피하려고 몬스터 ID와 NPC `decisions`는 문자열로 전달한다.

## 사용자 확인 항목

1. 게임 실행 후 JSON 파일이 갱신되고 화면에 NPC 140명과 마을 7곳이 보이는지.
2. 사냥·거래·약탈·이동 시 NPC 표와 상세 정보, 마을 집계 및 지도에 반영되는지.
3. 몹 사냥·리젠·보스 출현·사망·저장 불러오기 이후 개체 수와 기준이 맞는지.
4. P 일시정지 상태에서 수신은 유지되고 상태가 ‘게임 일시정지’로 바뀌는지.
5. 게임 종료 3초 후 갱신 중단 표시, 재실행 후 자동 재연결 및 추이 초기화가 되는지.
6. 사용자 지정 경로, 필터·정렬·NPC 선택·JSON 다운로드와 수신 모드가 동작하는지.

7개 마을·개별 주택·편지·소문·이사는 [마을 확장 안내](7개_마을_주택_소문_이사.md)를 참고한다. JSON에 houses 배열, NPC 주택·소문·이사 검토 시간, 마을의 빈집과 경제·안전·탐구 지표 및 사회 통신 누계를 추가했다. 행동 분포의 마지막 항목은 이사 중이다.
