NIGHT / LINK - 야간 도시 해킹 프로토타입
현재 기본 시작 레벨은 파밍 입문 레벨 1이다. 최신 조작과 진행은 레벨1_실행안내.txt를 참고한다.
이 문서는 초기 도시·해킹 시제품의 구조를 설명하며, 아래 첫 플레이와 저장 설명은 초기 버전 기준이다.
2026-09-15 변경: 문 개방과 실내 노출 대신 외부 단말로 건물 조명을 끄고 데이터를 원격 회수한다.
일반 몬스터는 시작 지점 주변에 배치되며, 입문 구역 밖과 보스 클리어 후에도 생성된다.
작성일: 2026-09-09

상태
사용자 요청에 따라 코드 구현만 진행했다.
이번 변경에 대한 빌드, 실행, 테스트, 화면 캡처 및 렌더링 결과 확인은 수행하지 않았다.
아래 설명은 구현한 기능과 사용자가 직접 확인할 절차이며, 실행 성공을 확인한 보고서가 아니다.
NIGHT / LINK는 시제품 화면에 사용한 임시 명칭이다.

1. 구현 범위
- C++ / OpenGL 기반 Windows 데스크톱 프로그램.
- 비스듬한 아이소메트릭 투영을 사용하는 2.5D 화면.
- 외부 이미지 없이 삼각형 배치로 그리는 빌딩, 창문, 간판, 네온, 도로.
- 항상 밤인 색감과 고정된 시간 표시. 게임 경과 시간은 별도로 흐른다.
- 키보드 이동, 달리기, 부드럽게 따라오는 카메라, 확대 및 축소.
- 건물 충돌과 간단한 건물 앞뒤 가림 처리, 가려져도 남는 플레이어 위치 표시.
- 플레이어 주변 청크의 생성과 해제. 같은 시드와 좌표에 같은 건물 배치.
- 카메라, 출입문, 전력 릴레이를 스캔하고 가까운 기기에 접속.
- E를 누르고 유지하는 해킹 진행, 카메라 감시와 추적 수치, 일시 접속 차단.
- 정전 지역의 전력 복구, 보상 지급, 해킹 속도 성장.
- 출입문 개방 시 실내를 단순하게 드러내는 표현과 데이터 회수.
- 구역별 문, 카메라, 정전 해결, 데이터 회수 상태와 플레이어 위치 저장.
- HUD: 현재 구역, 목표, 추적 수치, 크레딧, 간단한 지도와 조작 안내.

2. 사용자가 빌드할 때
권장 시작 구성은 기존 환경과 같은 Visual Studio 2022 / Debug / x64이다.
SimpleGame.sln을 열어 SimpleGame 프로젝트를 빌드하고 실행한다.
C++17, UTF-8 소스 처리, Windows SDK와 OpenGL 3.3 이상을 요구한다.
기존 GLEW와 freeglut 헤더, 라이브러리, DLL을 그대로 사용한다.

기본 x64 Debug 출력 위치:
  x64\Debug\SimpleGame.exe

실행 파일 옆에 필요한 파일:
  glew32.dll
  freeglut.dll
  Shaders\SolidRect.vs
  Shaders\SolidRect.fs
  Shaders\Fullscreen.vs
  Shaders\Downsample.fs
  Shaders\GaussianBlur.fs
  Shaders\Composite.fs

프로젝트의 빌드 후 처리에서 셰이더를 출력 폴더로 복사하도록 설정했다.
DLL은 저장소에 있던 각 플랫폼 및 구성별 출력 폴더의 파일을 사용한다.
출력 폴더를 사용자 지정하거나 배포할 때는 해당 플랫폼의 DLL도 함께 배치해야 한다.
셰이더와 저장 파일 경로는 실행 파일 위치를 기준으로 결정한다.
새로 빌드하기 전의 기존 실행 파일에는 이번 변경이 반영되어 있지 않다.

3. 조작법
W / A / S / D : 화면 방향을 기준으로 이동
Space + 이동 : 달리기
Tab          : 스캔 연결선 및 장치 강조 켜기 / 끄기
E 길게 누름  : 가까운 장치 해킹. 이동 중에는 진행이 취소된다.
+ 또는 =     : 확대
-            : 축소
P            : 일시 정지 / 재개
K            : 수동 저장
Esc          : 저장 후 종료
O / B / V / F: 전체 후처리 / 블룸 / 비넷 / 가장자리 블러 켜기 및 끄기
[ / ]        : 후처리 노출 감소 / 증가
, / .        : 블룸 강도 감소 / 증가
1 / 2        : 비넷 강도 감소 / 증가
3 / 4        : 가장자리 블러 강도 감소 / 증가

후처리의 구조와 추가 설정은 후처리_구현안내.txt를 참고한다.

기기는 일정 거리 내에서 가장 가까운 대상이 자동으로 선택된다.
대상 이름은 화면 하단과 장치 위에 표시된다.
해킹은 한 번 완료하면 E를 놓았다가 다시 눌러야 재시작한다.
스캔을 꺼도 가까운 장치에 접속할 수 있다.

4. 첫 플레이 흐름
신규 저장으로 시작하면 0:0 구역은 정전 상태이고 플레이어는 전력 릴레이 근처에 있다.

1) 화면 하단의 TARGET / POWER RELAY를 확인한다.
2) 움직이지 않고 E를 유지하여 전력을 복구한다.
3) 빌딩 불빛과 목표 표시가 바뀌는지 확인한다.
4) 전력 복구 보상 150 CR을 얻으면 해킹 시간이 1.8초에서 1.35초로 줄어든다.
5) 건물 외곽을 따라 출입문으로 이동하고 TARGET / ACCESS DOOR를 확인한다.
6) E로 문을 열고 건물 남쪽의 문 틈으로 들어간다.
7) 드러난 실내의 DATA 표시에 가까이 가면 데이터를 자동 회수한다.
8) 75 CR 보상 이후 다른 구역으로 이동해 탐험한다.

카메라가 켜진 구역에서 해킹하면 추가 추적이 발생한다.
카메라를 해킹하여 감시를 끄거나, 조작을 멈추어 추적을 낮출 수 있다.
추적이 100에 도달하면 8초 동안 접속이 차단된다.
정전 중인 문과 카메라는 릴레이 복구 전에는 해킹 명령을 실행하지 않는다.
문을 다시 잠그려면 플레이어가 실내와 문 영역에서 완전히 나와야 한다.

5. 저장과 재방문
실행 파일 옆의 night_city.save에 저장한다.
20초마다, 중요한 해킹 및 데이터 회수 후, K 입력과 종료 시 저장한다.
임시 파일을 쓴 다음 기존 파일과 교체하여 저장한다.
월드의 기본 건물 배치 전체 대신 시드와 변경 내용을 보관한다.
완료한 정전 이벤트와 이미 회수한 데이터에는 중복 보상을 지급하지 않는다.

새 게임을 시작하려면 프로그램을 종료하고 night_city.save를 다른 이름으로 옮겨 보관한다.
읽을 수 없거나 버전이 맞지 않는 저장 파일을 발견하면 원본을 보호하기 위해 자동 덮어쓰기를 중단한다.
이 경우 해당 파일을 별도 보관한 뒤 프로그램을 다시 시작한다.
Debug와 Release는 실행 파일 폴더가 다르므로 기본 저장 파일도 서로 다르다.
게임을 종료한 동안은 사건과 추적 시간이 진행하지 않는다.

6. 현재 한계 및 후속 구현
- 도시 구역은 한 종류이며, 도로 형태와 네 개의 건물 자리 배치는 규칙적으로 반복된다.
- 정전 이벤트는 해당 좌표의 생성 규칙에 따라 존재한다. 시간에 따라 새 사건을 추첨하는 감독 시스템은 아직 없다.
- 첫 정전 이벤트는 복구 경로만 제공한다. 전력 우회 선택과 연쇄 사건은 후속 범위이다.
- 문이 열리면 해당 건물 전체를 낮은 실내 표현으로 전환한다. 상세한 다층 건물 내부는 없다.
- 카메라의 탐지 판정은 기기 주변 거리 기준이다. 화면의 부채꼴은 장식이며 실제 시야 및 벽 차단 판정은 후속 범위이다.
- 움직이는 차량은 배경 연출이다. 교통 AI, 충돌, 수송대 사건은 없다.
- 본격적인 NPC, 전투, 세력 관계, 장비 트리, 의뢰 대화는 없다.
- 건물 가림은 단순한 정렬 규칙을 사용한다. 복잡한 교차 구조는 후속 개선이 필요하다.
- 청크 생성은 현재 주 스레드에서 처리한다. 비동기 스트리밍과 성능 최적화는 후속 범위이다.
- 활성 청크는 화면 크기와 확대율에 따라 반경 2~6청크만 유지한다.
- 좌표는 double 월드 좌표이며 카메라를 뺀 뒤 float로 렌더링한다.
  시제품은 각 축 +/- 1조 월드 단위에서 이동을 제한한다. 수학적인 무한 좌표 구현은 아니다.
- 탐험으로 생긴 변경 기록은 저장 공간에 계속 누적된다. 압축과 오래된 기록 정리는 후속 범위이다.
- 읽기 보호를 위해 저장 파일당 변경 청크 100만 개를 상한으로 둔다.
- UI는 자체 영문 비트맵 글꼴을 사용한다. 한글 UI는 폰트 렌더링 체계 추가 이후 지원한다.
- 해킹은 게임 속 가상 장치를 조작하며 외부 네트워크에는 접속하지 않는다.

7. 주요 소스 역할
SimpleGame.cpp : 창, OpenGL 초기화, 타이머, 입력 및 종료 처리
Renderer.h/cpp : 화면 좌표 삼각형 배치, 선, 도형, 글자와 광원 느낌의 표현
World.h/cpp    : 청크 생성, 충돌, 기기 배치, 영속적인 구역 상태와 저장
Prototype.h/cpp: 플레이 흐름, 카메라, 해킹, 사건, 건물 및 HUD 그리기
Shaders        : 위치와 색상을 전달하는 OpenGL 3.3 셰이더

8. 직접 확인할 때 우선 볼 항목
- 빌드 및 출력 폴더에서 실행할 때 셰이더와 DLL을 정상적으로 찾는가?
- 첫 화면에서 플레이어와 전력 릴레이, 해킹 목표를 알아볼 수 있는가?
- 정전 복구 전후에 건물 조명이 바뀌는가?
- 벽을 통과하지 않고 문을 열어 내부 데이터까지 이동할 수 있는가?
- 청크 경계를 넘어 이동하고 돌아와도 건물과 완료 상태가 유지되는가?
- 종료 후 재실행 시 위치, 보상과 이벤트 상태가 복원되는가?
- 창 크기 변경, 확대 및 축소에서 UI와 장면이 읽기 쉽게 유지되는가?
- 장시간 이동 시 프레임 지연이나 메모리 증가가 허용 가능한가?

이번 작업에서는 위 항목을 실행하여 확인하지 않았다.
