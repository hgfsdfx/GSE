NIGHT / LINK - 메시 캐시와 셰이더 파일 구조

2026-09-21: Actor/SceneGraph가 배치·수명·그리기 순서를 관리한다.
아래 Renderer와 MeshCache는 Actor가 요청한 도형의 배치 및 GPU 메시 재사용을 담당한다.
지면 캐시 키에는 소속 건물 Actor의 위치와 크기도 포함하여 그림자 변경을 반영한다.
Actor_SceneGraph_구조.md에 구조와 확장 방법을 정리했다.

기본 성능 프로파일 로그
- 실행 콘솔에 약 1초마다 [Profile] 로그를 출력한다. 집계는 매 렌더링 프레임마다 수행한다.
- FPS: 해당 구간에 버퍼 교환까지 마친 프레임 수 / 실제 경과 시간.
- FrameMs(avg): 같은 구간의 평균 프레임 간격(ms). GPU 실행 시간만 측정한 값은 아니다.
- DrawCalls/frame: 최근 프레임(last), 구간 평균(avg), 최솟값(min), 최댓값(max).
- 월드의 캐시 메시/동적 배치, HUD, Bloom/블러/최종 합성의 실제 glDrawArrays 호출을 포함한다.
- 도형이나 Actor 개수는 세지 않는다. glDrawBuffer는 출력 대상 설정이므로 draw call에서 제외한다.
- 후처리를 끄거나 사용할 수 없는 경우 실행되지 않은 후처리 패스는 집계되지 않는다.
- 추후 glDrawElements 등 새 draw 제출 경로를 추가할 때 해당 카운터도 증가시켜야 한다.
- FPS에는 업데이트, 타이머(현재 16ms), 버퍼 교환 대기가 포함된다.

1. 정적 메시의 GPU 캐싱

MeshCache.h/cpp에서 생성한 메시의 VAO와 VBO를 보관한다.
처음 필요한 메시만 GL_STATIC_DRAW로 GPU에 올린다.
같은 키가 다시 요청되면 정점 생성과 GPU 업로드를 생략하고 기존 메시를 그린다.

캐시 대상
- 청크의 지면, 도로, 보도, 차선, 횡단보도와 건물 그림자.
- 건물 외벽, 지붕, 창문, 간판, 옥상 설비와 안테나 기둥.

지면은 월드 시드와 청크 좌표로 식별한다.
건물은 폭, 깊이, 높이, 스타일과 실제 조명 켜짐/꺼짐 상태로 식별한다.
위치가 달라도 모양과 상태가 같은 건물은 같은 GPU 메시를 사용한다.
전력이나 조명 해킹 상태가 바뀌면 그 상태에 맞는 캐시를 사용하거나 새로 만든다.
조명 해킹 후에도 건물 높이와 외형은 유지되며, 창문과 간판의 발광만 사라진다.
기존 상태로 되돌아오면 캐시에 남아 있는 메시를 재사용한다.

메시는 카메라와 무관한 로컬 투영 좌표로 저장한다.
이동과 확대/축소는 SolidRect.vs의 u_ModelTransform으로 적용한다.
화면 크기는 u_Viewport로 반영하므로 이동, 줌, 리사이즈가 캐시 키를 바꾸지 않는다.
정적 메시의 선 두께와 글자도 메시 전체와 함께 확대/축소된다.

2. 동적 도형과 출력 순서

차량, 점멸등, 스캔 표시, 캐릭터, 적, 발사체와 변하는 HUD는 동적으로 갱신한다.
원은 분할 수별 단위원 좌표를, 글자는 유니코드 문자별 획과 투명도를 CPU에서 캐싱한다.
원과 글자를 다시 그릴 때는 캐시 좌표에 위치, 크기와 색상을 적용한다.
이 동적 도형들의 최종 정점은 계속 동적 VBO에 업로드한다.

Renderer는 정적 메시와 동적 배치를 요청 순서대로 보관한 뒤 출력한다.
건물과 캐릭터 사이의 기존 깊이 정렬 및 반투명 도형의 순서를 유지한다.
월드 출력 뒤 기존 HDR/Bloom 후처리를 적용하고, 마지막에 HUD를 그린다.
캐시에는 색상과 발광 값도 들어 있으므로 정적 발광 면에도 Bloom이 적용된다.
후처리용 VAO도 기존처럼 초기화 시 한 번 만든 뒤 재사용한다.
전체 화면 삼각형은 Fullscreen.vs의 gl_VertexID로 생성하므로 별도 VBO 업로드가 없다.

3. 캐시 수명과 메모리

MeshCache의 기본 제한은 512개 메시, 정점 버퍼 합계 64 MiB이다.
120프레임 동안 사용하지 않은 메시는 정리한다.
용량이 부족하면 가장 오래 사용하지 않은 메시부터 제거한다.
현재 프레임의 출력 명령이 참조하는 메시는 제거하지 않는다.
한도를 넘거나 버퍼 할당이 실패하면 해당 메시를 동적 배치로 그린다.
종료할 때 캐시의 VAO/VBO를 해제한다.
CPU의 원 좌표 캐시는 분할 수 3~128이다.
FontGlyphCache는 실제 사용한 유니코드 글자를 필요할 때 생성하여 Renderer 수명 동안 보관한다.

한글 렌더링 (2026-09-22)
- Renderer::Text에 UTF-8 문자열을 전달한다. TextWidth는 같은 글꼴의 실제 글자 폭을 반환한다.
- Windows 맑은 고딕을 우선 사용하고, 한글을 지원하지 않으면 굴림을 시도한다.
- GetGlyphOutlineW로 최초 한 번만 글자 비트맵을 읽고, 같은 농도의 가로 구간을 캐싱한다.
- 획을 기존 도형 배치에 합치므로 글자마다 별도의 glDraw 호출을 추가하지 않는다.
- 한글은 기존 5×7 영문 비트맵보다 획이 복잡하여 정점 수와 CPU 조립 비용이 늘 수 있다.
- 별도 폰트 파일 배포는 필요 없으며, 실행 환경에 한글 지원 Windows 폰트가 필요하다.
- Gdi32.lib를 사용하며 프로젝트의 /utf-8 옵션으로 소스와 실행 문자열 인코딩을 통일한다.
- 창 제목은 Unicode Win32 API, 콘솔 안내는 UTF-8로 출력한다.
- API 참고: https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getglyphoutlinew

4. 셰이더 파일

셰이더 코드는 SimpleGame/Shaders 아래의 독립 파일로 관리한다.
C++ 문자열에 GLSL 소스를 넣지 않고 ShaderProgram.cpp에서 파일을 읽어 컴파일한다.
기존 코드도 파일 분리 상태였으며, 이번 변경에서는 캐시 좌표 변환을 .vs에 추가했다.
로더는 vertex shader의 .vs 및 fragment shader의 .fs 확장자를 확인한다.

파일 조합과 역할
- SolidRect.vs + SolidRect.fs
  정적 메시/동적 도형의 좌표 변환, 색상, 발광 처리.
- Fullscreen.vs + Downsample.fs
  HDR 장면 축소와 Bloom용 밝은 영역 추출.
- Fullscreen.vs + GaussianBlur.fs
  Bloom과 주변부 흐림에 사용하는 가로/세로 블러.
- Fullscreen.vs + Composite.fs
  Bloom 합성, 비넷, 주변부 흐림, 노출과 톤 매핑.

실행 파일과 같은 폴더의 Shaders 폴더에서 셰이더를 로드한다.
Visual Studio 프로젝트의 CopyPrototypeShaders 단계가 빌드 후 .vs/.fs 파일을 복사한다.
셰이더를 수정한 뒤 빌드하거나 실행 폴더에 해당 파일을 복사하고 게임을 재시작한다.
실행 중 셰이더 자동 재로딩은 포함하지 않는다.

5. 새 정적 메시 추가 방법

Renderer::BeginCachedMesh(key, screenOrigin, zoom)를 호출한다.
- false: 기존 메시의 출력이 이미 예약되었으므로 추가 정점 생성은 생략한다.
- true: 로컬 좌표로 Triangle/Quad/Line/Text 등을 호출하고 EndCachedMesh()로 끝낸다.

키에는 정점, 색상, 발광 값을 바꾸는 모든 상태를 포함해야 한다.
기록 중에는 화면 좌표, 카메라, 시간에 따른 애니메이션 값을 넣지 않는다.
캐시 기록을 중첩하지 않으며 BeginCachedMesh와 EndCachedMesh를 한 쌍으로 사용한다.

사용자 요청에 따라 빌드, 실행, 테스트와 렌더링 결과 확인은 진행하지 않았다.
실제 성능 변화와 화면 결과는 실행 환경에서 확인해야 한다.
