1. 변경 목적

기존에는 건물 등의 캐시 메시를 개별 VAO/VBO로 보관하고 메시마다 glDrawArrays를 호출했다.
동적 도형과 한글은 CPU에서 화면 좌표 정점을 매 프레임 조립하여 업로드했다.
새 구조에서는 메시 원형과 인스턴스 데이터를 분리하고, 서로 다른 메시도 공통 저장소에서 참조한다.

Actor/SceneGraph의 출력 요청 순서를 그대로 따른다.
메시 종류별로 다시 정렬하지 않으므로 반투명 도형과 건물/캐릭터의 앞뒤 관계를 유지한다.
월드 배치 → HDR 후처리 → HUD 배치 순서다.

2. 배치 방식

- MeshCache: 정점의 위치·색상·발광을 공통 GPU texture buffer에 보관한다.
- 메시 인스턴스: 위치, X/Y 축 변환, 색상, 투명도, 발광을 전달한다.
- 삼각형 참조: 원형 메시 안의 첫 정점 번호와 해당 메시 인스턴스 번호만 전달한다.
- SolidRect.vs: gl_VertexID와 참조 번호로 저장된 정점 및 변환을 읽는다.
- Renderer::Flush: glDrawArraysInstanced(GL_TRIANGLES, 0, 3, 참조 개수)를 한 번 호출한다.

OpenGL 3.3을 유지하기 위해 삼각형 단위 인스턴싱과 vertex pulling을 조합했다.
하나의 메시를 여러 번 배치해도 원형 정점 데이터는 중복 업로드하지 않는다.
서로 다른 정점 수의 건물·글자·기본 도형을 같은 배치에서 처리할 수 있다.
매 프레임 업로드되는 것은 인스턴스와 삼각형 참조이며, 변형된 전체 메시 정점이 아니다.

한 배치는 최대 1,048,576개 삼각형 참조와 최대 65,536개 메시 인스턴스다.
GPU의 GL_MAX_TEXTURE_BUFFER_SIZE가 작으면 인스턴스 상한도 낮춘다.
상한을 넘으면 순서를 유지하면서 나누어 제출한다.

기본 후처리 설정에서 배치가 분할되지 않는 경우의 코드상 호출 수:
- 월드 1회 + HUD 1회
- Bloom 추출 1회 + 블러 6회
- 주변부 흐림 축소 1회 + 블러 4회
- 최종 합성 1회
합계 15회다. 이는 실행 측정값이 아니며 화면 내용, 배치 분할, 효과 설정에 따라 달라진다.
후처리를 끄면 후처리 호출은 사라진다.
glDrawBuffer는 출력 대상 설정이므로 draw call 집계에서 제외한다.

3. 재사용 대상

- 삼각형: 공통 단위 삼각형을 위치와 두 축으로 변환한다.
- 사각형, 선분: 공통 단위 사각형을 크기·방향에 맞춰 인스턴싱한다.
- 일반 사변형: 평행사변형은 사각형 1개, 나머지는 삼각형 2개로 표현한다.
- 원: 분할 수별 단위원 메시를 캐싱한다.
- 링: 캐시된 단위 사각형을 선분으로 배치한다. 반지름과 두께 변경은 인스턴스 변환이다.
- 한글/숫자/기호: 글자 전체의 획 메시와 글자 폭을 캐싱한다.
- 건물, 간판, 지면: 기존 BeginCachedMesh/EndCachedMesh 호출로 완성된 메시를 캐싱한다.
- 캐릭터, 적, 발사체, 효과, HUD: 위 기본 메시를 조합한 인스턴스를 제출한다.

글자는 최초 캐시 미스에서만 GDI의 글자 획을 메시로 만든다.
일반 텍스트 출력은 글자마다 인스턴스 하나를 제출하며 매 프레임 획 정점을 다시 조립하지 않는다.
정적 건물 메시 안의 간판은 건물 메시를 처음 만들 때만 포함된다.
애니메이션 위치·색상·체력바 길이와 삼각형 참조 목록은 매 프레임 갱신해야 하는 데이터다.

4. 파일 캐시

위치: 실행 파일 옆 MeshCache/v3/*.gmesh
실행 콘솔에도 절대 경로를 출력한다. 빌드나 별도 캐시 생성 도구 실행은 필요 없다.
첫 실행 또는 새로운 메시: 생성 → 파일 저장 → GPU 업로드.
같은 실행에서 재사용: 메모리/GPU 캐시 참조.
다음 실행 또는 메모리에서 제거된 메시: 파일 읽기 → GPU 업로드 → 인스턴싱.

파일에는 다음을 저장한다.
- 매직 값, 형식 버전, 전체 캐시 키
- 정점 개수, 정점 데이터, 글자 전진 폭
- 키·전진 폭·정점 데이터의 체크섬

파일명은 키의 안정적인 해시다. 해시 충돌은 파일 내부의 전체 키 비교로 감지한다.
크기, 삼각형 배수, 유한한 수치, 버전과 체크섬이 맞지 않으면 캐시 미스로 처리해 재생성한다.
임시 파일을 쓴 후 교체하므로 불완전한 쓰기가 정상 캐시로 노출되지 않도록 한다.
저장 권한이나 디스크 오류가 발생하면 메모리 캐시로 계속한다.
캐시에는 게임 진행 상태를 저장하지 않는다. 저장 게임과 별개다.

디스크 예산은 시작 시 폴더를 집계하여 256 MiB / 8,192개 파일로 제한한다.
예산에 도달하면 기존 파일을 보존하고 새 파일 저장을 생략한다.
기존 파일 읽기와 메모리 캐시는 계속 사용한다.
게임을 종료한 상태에서 이 생성 캐시 폴더를 비우면 다음 실행에 다시 생성한다.
.gitignore에 MeshCache 폴더를 등록했다.

GPU 정점 저장소의 상한은 64 MiB 또는 장치 제한 중 작은 값이다.
캐시 공간이 부족하면 다음 프레임 시작에 직전 프레임에서 사용하지 않은 메시를 제거하고 압축한다.
프레임 중에는 메시의 위치를 옮기지 않아 제출 중인 참조가 무효화되지 않는다.
기본 삼각형과 사각형은 상주한다.
한 프레임의 활성 메시만으로 예산을 넘으면 기본 도형 인스턴싱으로 출력하며,
해당 상황에서는 메시 조립/파일 읽기가 반복될 수 있으므로 프로파일 수치로 구분한다.
CPU에는 GPU 저장소 재배치를 위한 정점 사본도 남는다.

5. 캐시 키와 확장 방법

BeginCachedMesh(key, origin, scale)
- false: 파일 또는 메모리에서 찾은 메시의 인스턴스를 이미 등록했다.
- true: 로컬 좌표로 도형을 생성한 뒤 EndCachedMesh()를 호출한다.
- 중첩 기록은 지원하지 않는다.

DrawCachedMesh(key, origin, xAxis, yAxis, tint)
- 이미 저장된 메시를 추가로 배치한다.
- 변환의 두 축으로 회전·확대·비균일 스케일을 표현할 수 있다.
- 캐시를 찾으면 true, 없으면 false다.
- 흰색 원형 메시를 만들면 tint로 색상·투명도·발광을 바꿔 재사용할 수 있다.

키에는 원형 정점·색상·발광을 바꾸는 상태를 모두 포함한다.
카메라 이동과 인스턴스 위치·크기는 키에 넣지 않는다.
애니메이션 시간을 키에 넣어 매 프레임 다른 파일을 만들지 않는다.
건물 키에는 크기, 스타일, 조명 상태가 들어간다.
지면 키에는 월드 시드, 청크와 그림자에 영향을 주는 건물 위치·크기가 들어간다.
한글 캐시에는 실제 선택된 폰트 데이터의 해시와 래스터라이징 버전을 넣는다.
정적 건물 캐시에도 폰트 식별자를 넣어 간판 모양 변경을 반영한다.
메시 생성 규칙을 바꾸면 scene/glyph/primitive 키 버전 또는 저장 형식 버전을 올려야 한다.

6. 콘솔 프로파일 로그

기존 FPS, FrameMs(avg), DrawCalls/frame의 last/avg/min/max는 유지한다.
새 항목:
- UpdateMs(avg): 관측 구간의 게임 업데이트 1회 평균 경과 시간.
- DrawMs(avg): 화면 구성부터 배치 제출까지 프레임당 평균 경과 시간.
- SwapMs(avg): 버퍼 교환 호출의 프레임당 평균 경과 시간.
- MeshNew: 관측 구간에 새로 생성한 메시 수.
- MeshLoad: 관측 구간에 파일에서 읽어 GPU에 올린 메시 수.
- MeshHits: 관측 구간의 메모리 캐시 조회 성공 횟수.
- MeshUploadKiB(avg): 프레임당 원형 정점 업로드 용량.
- InstanceUploadKiB(avg): 프레임당 인스턴스 및 삼각형 참조 업로드 용량.
- Instances(last): 최근 프레임에서 제출한 메시 인스턴스 레코드 수.

고정 장면이 준비된 뒤 MeshNew와 MeshUploadKiB가 0에 가까운지 확인할 수 있다.
새 청크, 처음 보는 글자, 조명 상태 변경, 저장소 압축 시에는 원형 업로드가 발생할 수 있다.
재실행 초기에는 MeshNew보다 MeshLoad가 증가하는 것이 캐시 로딩 경로다.
DrawCalls는 실제 OpenGL draw 함수 호출 횟수이며 인스턴스 수와 다르다.
위 시간은 CPU에서 관측한 호출 경과 시간이며 GPU 타이머 쿼리 결과가 아니다.
DrawMs에는 드라이버 대기와 최초 메시 파일 I/O도 포함될 수 있다.
FPS에는 업데이트, 타이머(현재 16ms), 버퍼 교환 및 로그 출력 비용이 포함된다.

7. 관련 파일

Renderer.h/cpp: 배치 제출, 변환, 도형/글자 인스턴싱.
MeshCache.h/cpp: 공유 정점 저장소, 메모리 캐시, 프레임 경계 압축.
MeshCacheDisk.cpp: 파일 포맷, 검증, 저장과 로딩.
FontGlyphCache.h/cpp: 글자 최초 래스터라이징, 폰트 식별자.
Shaders/SolidRect.vs: 공유 메시 및 인스턴스 데이터 조회.
Shaders/SolidRect.fs: 색상, HDR 발광 처리.
PostProcessor: 기존 Bloom·비네트·주변부 흐림·톤 매핑 유지.
SimpleGame.cpp: 실제 draw 함수 호출 수와 성능 로그.

셰이더는 실행 파일 옆 Shaders 폴더에서 로드한다.
Visual Studio의 CopyPrototypeShaders 단계가 빌드 후 최신 .vs/.fs를 복사한다.
새 실행 파일에는 변경된 SolidRect.vs를 함께 사용해야 한다.

사용자 요청에 따라 빌드, 실행, 테스트 및 렌더링 확인은 진행하지 않았다.
실제 FPS와 draw call 감소량은 사용자 실행 결과로 확인해야 한다.
