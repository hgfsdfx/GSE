# 녹스 — NPC 리깅 및 로봇 몹 애니메이션 팩

기존 `nox_lowpoly`의 NPC 공용 파트 25개에 리깅을 추가하고, 외형이 다른 로봇 몹 7종을 제작했다. 게임 소스·빌드·NPC 실행 로직은 변경하지 않았다.

| 파일 / 폴더 | 내용 |
| --- | --- |
| `Nox_Rigged_NPC_and_Robots.blend` | 편집용 원본. NPC 공용 리그 1개, 로봇 리그 7개, 88개 Action |
| `NPC_Common_Animated.glb` | 고스트 파트 조합으로 확인할 수 있는 NPC 공용 리그·11개 애니메이션 |

| 4 | `04_Hound` | 4족 | 낮고 긴 몸통, 주둥이·귀 센서·꼬리, 추적견 실루엣 |

거미형은 이 팩의 4족 보행 규격에 맞춘 로봇이다. 몹 인덱스는 자산 ID이며 기존 게임의 `EnemyKind` 숫자와 자동으로 대응하지 않는다. 전투 역할·능력치 배정은 후속 구현에서 결정한다.

## 리깅

- NPC는 `SK_NPC_Common` 공용 본 16개를 사용한다. 머리·몸통·골반·좌우 상완·전완·손·허벅지·종아리·발과 루트로 구성한다.
- 2족 로봇은 각각 자기 비율에 맞춘 16개 본을 사용한다.
- 4족 로봇은 몸통·머리·꼬리와 앞뒤 좌우 다리를 포함한 17개 본을 사용한다.
- 모든 메시 정점에 정규화된 스킨 가중치가 있다. 로우폴리 외장과 기계 부품이 고무처럼 늘어나지 않도록 연결된 부품 단위로 본에 단단히 결합했다.
- 기존 NPC의 좌우 다리가 한 메시인 구조는 유지하면서, 각 다리·무릎 아래·발에 다른 본 가중치를 배정했다. 좌우 다리는 독립적으로 움직인다.
- 애니메이션은 발 목표 위치에서 관절 위치를 역산한 후 **매 프레임 FK 위치·회전·배율 키로 베이크**했다. 재생 시 Blender IK 제약이나 외부 스크립트는 필요 없다.
- 원본은 본의 FK 키프레임을 직접 편집할 수 있다. 별도의 IK 조작 핸들을 갖춘 애니메이터용 컨트롤 리그는 포함하지 않는다.

NPC의 기존 파트 인덱스는 변경하지 않았다. 남녀 체형·헤어·갑옷·로봇 파트 모두 같은 NPC 스켈레톤을 공유한다. `NPC_Common_Animated.glb`는 고스트 외형 예시이며, 다른 NPC는 `npc_presets.json`의 슬롯 인덱스로 조립한다.

개별 파트 GLB를 불러오면 각 파일에 스켈레톤이 들어 있다. 후속 로더에서는 본 이름과 bind pose를 기준으로 **한 NPC 스켈레톤에 스킨을 연결**해야 한다. 파일마다 독립적인 애니메이션 플레이어를 만드는 구조를 전제로 하지 않는다. 팔레트 정보는 카탈로그에 포함되어 있다.

## 각 리그의 애니메이션 11개

| 클립 | 반복 | 내용 |
| --- | --- | --- |
| `Idle` | 예 | 작은 대기 움직임, 2초 |
| `Walk` | 예 | 발 디딤을 고려한 걷기. 체형별 주기 |
| `Run` | 예 | 더 큰 보폭, 팔 스윙·몸 기울기. 체형별 주기 |
| `Turn_L_45` | 아니오 | 제자리 좌회전 45°, 1.6초 |
| `Turn_R_45` | 아니오 | 제자리 우회전 45°, 1.6초 |
| `Turn_L_90` | 아니오 | 제자리 좌회전 90°, 약 2.133초 |
| `Turn_R_90` | 아니오 | 제자리 우회전 90°, 약 2.133초 |
| `Jump` | 아니오 | 준비 → 도약 → 공중 → 착지 → 자세 회복, 1.2초 |
| `Jump_Start` | 아니오 | 전체 점프의 0~10프레임, 약 0.333초 |
| `Jump_Air` | 아니오 | 전체 점프의 10~26프레임, 약 0.533초 |
| `Jump_Land` | 아니오 | 전체 점프의 26~36프레임, 약 0.333초 |

Blender Action 이름은 `<리그 ID>__<클립>`이다. 예: `04_Hound__Run`. GLB 안에서는 `Run`과 같은 공통 클립 이름을 사용한다.

### 디딤 방식

- 2족은 좌우 교대 디딤과 반대편 팔 스윙을 사용한다.
- 4족 걷기는 네 발을 순차적으로 착지시키며, 긴 접지 구간으로 지지를 유지한다.
- 4족 달리기는 대각선 다리를 짝지은 속보 형태다. 하운드·거미형은 짧은 공중 구간을 갖고, 무거운 갑충형·수송형은 접지 시간을 더 길게 둔다.
- 방향 전환은 루트만 회전시키지 않고 발을 번갈아 떼어 다시 놓는다. 회전 시작·종료의 각속도를 완만하게 바꿨다.
- 점프는 준비 웅크림, 도약 시 팔 움직임, 공중 다리 접기, 착지 후 충격 흡수 자세를 포함한다. 무거운 로봇은 점프 높이와 움직임을 작게 설정했다.

### 이동 속도

걷기·달리기는 **제자리 애니메이션**이다. 접지한 발이 뒤로 움직이는 속도에 맞춰 게임 캐릭터를 앞으로 이동시켜야 발 미끄러짐을 줄일 수 있다.

| 리그 | 걷기 m/s | 달리기 m/s |
| --- | ---: | ---: |
| NPC 공용 | 0.469 | 1.560 |
| Sentinel | 0.586 | 1.950 |
| Strider | 1.000 | 3.467 |
| Juggernaut | 0.424 | 0.950 |
| Hound | 0.440 | 1.857 |
| Scarab | 0.240 | 0.722 |
| Spider | 0.427 | 1.688 |
| Mule | 0.337 | 0.948 |

표는 배율 1의 미터 기준이다. 정확한 값은 카탈로그를 따른다. 기존 게임 이동 수치를 그대로 적용하기 전에 월드 단위와 모델 배율을 맞춰야 한다. 이동 속도를 바꾸면 애니메이션 재생률도 함께 조정한다.

## 방향 보간 및 점프 적용 규칙

- 방향 전환 클립에는 **루트 회전**이 들어 있다. 루트 회전을 월드 캐릭터로 추출하거나, 스켈레톤 루트에 유지하는 방식 중 하나를 선택한다. 두 곳에 같은 회전을 중복 적용하지 않는다.
- 45°·90° 클립은 목표 회전량에 따라 선택·시간 정규화·블렌딩할 수 있다. 실제 상태 전이·회전 보간 코드는 포함하지 않았다.
- 걷기↔달리기의 블렌딩은 좌우 디딤 위상을 맞춰 시작하는 것이 좋다. 단순히 아무 프레임에서 섞으면 발 고정이 풀릴 수 있다.
- 점프에는 루트의 수직 궤적이 있다. 게임 물리의 점프 높이와 이 수직 이동을 중복해서 더하지 않는다.
- 분할 점프는 원래 전체 점프의 좌표를 유지한다. `Jump_Start` 마지막과 `Jump_Air` 처음, `Jump_Air` 마지막과 `Jump_Land` 처음이 같은 포즈다. 구간별 수직 이동을 임의로 0으로 재설정하면 연결이 끊어진다.
- `Jump_Air`는 고정된 공중 구간이며 반복용이 아니다. 임의의 체공 시간, 낙하 높이, 경사면 접지를 처리하는 런타임 시스템은 후속 작업 범위다.

## 편집·좌표

- 미터 단위. Blender는 Z-up / 정면 -Y, GLB는 Y-up / 정면 +Z.
- GLB들은 원점에서 내보냈다. Blender 원본의 좌우·앞뒤 배치는 전시용이다.
- Blender 기본 화면에는 고스트 예시와 7개 몹이 표시된다. NPC의 다른 파트는 숨김 상태다. `NPC_Common` 컬렉션에서 원하는 슬롯만 표시해 조합한다.
- 한 슬롯의 여러 파트를 동시에 켜면 중첩된다. 파트 이름과 인덱스는 `rig_catalog.json`을 따른다.
- Action Editor에서 해당 리그의 Action을 선택하면 키프레임을 편집할 수 있다. NLA 트랙은 내보내기용으로 클립별 저장되어 있으며 기본적으로 음소거했다.
- 단일 NPC 리그의 파트를 다른 리그에 연결할 때는 리그별 비율을 확인한다. 7개 로봇은 체형별 스켈레톤이므로 NPC 애니메이션을 이름만 보고 그대로 공유하는 구조가 아니다.

## 검증 범위

- NPC 25개 파트와 몹 7개 메시의 정점 가중치 합과 본 참조를 확인했다.
- 88개 클립을 베이크하는 모든 키프레임에서 다리 길이로 발 목표에 도달 가능한지 확인했다.
- 각 클립의 대표 포즈에서 실제 평가된 발 본 위치, 표시 메시의 지면 침범, 반복 클립의 처음·끝 포즈를 검사했다.
- 분할 점프 연결부와 전체 점프의 같은 시점이 일치하는지 검사했다.
- GLB 8개의 애니메이션 이름·시간·스킨 데이터를 확인하고, 빈 Blender 장면에 재수입하여 각 클립의 시작·중간·끝 포즈를 검사했다.
- 렌더한 걷기·달리기·점프·회전 포즈를 비교했다. 검사 수치는 JSON에 남겼다.

지면은 평면 기준이다. 실제 엔진의 보간기, 상태 전이, 월드 단위, 충돌·물리 및 경사면 IK를 연결한 뒤에는 해당 환경에서 움직임을 확인해야 한다. 현재 게임 실행 검증이나 빌드는 수행하지 않았다.
